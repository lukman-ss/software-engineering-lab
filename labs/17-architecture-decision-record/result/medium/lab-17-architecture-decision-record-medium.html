Konteks Arsitektur Hilang Tanpa Jejak

Keputusan arsitektur sering lahir di chat atau meeting. Saat tim berubah, alasan awalnya hilang. ADR membuat alasan itu bisa ditelusuri lagi.

Review Manual Melewatkan Relasi Supersesi

Masalah terbesar review manual adalah supersesi yang tidak sinkron. ADR baru menyatakan menggantikan, tetapi ADR lama tetap bertanda aktif karena lupa diperbarui.

ADR Bukan Dokumen, Tapi Record

ADR bukan sekadar dokumen naratif. Saat diubah menjadi struct Record, mesin bisa mengekstrak field kunci dan memeriksa konsistensi secara otomatis.

Pipeline Validasi Empat Tahap

Pipeline-nya sederhana: Markdown dibaca, field penting diekstrak, lalu linter memeriksa aturan graf.

Struct Record: Fondasi Validasi Data

Struct Record mendefinisikan field wajib secara eksplisit. Dengan integer dan enum, linter memeriksa aturan tanpa perlu menebak teks bebas.

type Record struct {
    ID           int
    Title        string
    Status       Status
    SupersededBy int // 0 jika aktif
    Supersedes   int // 0 jika tidak menggantikan
    Content      string
}

Deteksi Tautan Supersesi Patah

Linter memeriksa keberadaan setiap ID referensi. Jika ADR merujuk ke nomor yang belum ada, error spesifik langsung dihasilkan sebelum merger.

ADR 1: Status Superseded by 99
→ Error: superseded by non-existent ADR 99

ADR 1: Status Accepted, Supersedes: 99
→ Error: supersedes non-existent ADR 99

Biaya Tersembunyi: Lineage Drift Menumpuk

Masalah ADR rusak bukan langsung terlihat. Ia menumpuk sampai keputusan baru bergantung pada catatan lama yang salah.

Eksperimen memvalidasi tiga ADR nyata: monolit awal, service pengganti, dan usulan ditolak agar argumen penolakan tidak diperdebatkan ulang.

Lolos Linter Bukan Berarti Keputusan Benar

Nomor ID berurutan tanpa celah. Relasi timbal-balik utuh tanpa tautan gantung. Tidak ada siklus ketergantungan antar-dokumen. Kebenaran argumen teknis di bagian Decision. Apakah rancangan arsitektur tepat untuk kapasitas tim. Evaluasi dampak performa dan biaya operasional sistem.

Trade-off: Struktur Baku vs Fleksibilitas

Wajib tiga bagian: Context, Decision, Consequences. Status dibatasi lima enum resmi. Memungkinkan CI gate otomatis dan deterministik. Tidak mendukung format narasi paragraf bebas. Memerlukan disiplin tim mengisi field relasi. Perubahan format membutuhkan penyesuaian parser.

Validasi Paralel dengan Mutex

Validasi paralel mengumpulkan error secara race-safe memakai mutex. Pola ini terbukti aman pada pengujian konkurensi Go.

for _, r := range records {
    wg.Add(1)
    go func(rec *Record) {
        defer wg.Done()
        localErrs := validate(rec)
        mu.Lock()
        errs = append(errs, localErrs...)
        mu.Unlock()
    }(r)
}

Sebelum vs Sesudah Validasi Otomatis

Tautan supersesi sepihak sering terlewat. Nomor meloncat sulit disadari saat banyak file. Status non-standar masuk tanpa sengaja. Semua inkonsistensi ditolak otomatis di CI. Nomor ID wajib monotonik dan teratur. Relasi timbal-balik divalidasi deterministik.

Batasan Lab: Hanya Validasi Format

Ekstraksi regex dari string Markdown. Pemeriksaan nomor urut dan relasi timbal-balik. Deteksi siklus pada graf supersesi. Tidak menilai kebenaran argumen keputusan. Simulasi in-memory, bukan pembacaan ribuan berkas disk.

Kasus Batas: Menghentikan Fitur Tanpa ADR

Menghentikan fitur tanpa ADR Deprecated menciptakan gap antara catatan dan kode aktual. Dokumen lama tetap terlihat aktif dan membingungkan tim berikutnya.

Bukti yang Divalidasi oleh Test Suite

Test membuktikan parser dan linter bekerja sesuai aturan pada skenario uji. Bukti ini menegaskan keandalan logika struktural, bukan jaminan semua kebutuhan tim terpenuhi.

Batas Integritas: Apa yang Tidak Diuji

Test unit membuktikan aturan pada input tertentu. Keberhasilan test bukan bukti bahwa keputusan yang didokumentasikan sudah siap diterapkan di production.

Risiko Kepalsuan: Linter Hijau Bukan Aman

Linter hijau hanya menjamin format valid, bukan kualitas desain. Jangan jadikan status lolos linter sebagai pengganti telaah arsitektur mendalam oleh engineer senior.

Panduan Implementasi Linter ADR di Tim

Tetapkan template berkas: Context, Decision, Consequences. Gunakan enum status resmi (Accepted, Superseded, Rejected). Pasang parser dan linter pada CI gate pull request. Larang edit retroaktif: keputusan baru wajib nomor baru.

Anti-Pattern: Kesalahan Adopsi ADR

Anti-pattern paling berbahaya adalah suntingan diam-diam pada keputusan lama. Hal ini menghapus riwayat pembelajaran tim dan memicu kebingungan bagi engineer baru.

Reproduksi Mandiri di Mesin Lokal

Lab ini zero-dependency dan dapat direproduksi langsung. Menjalankan demo dan test membuktikan parser dan linter bekerja secara mandiri di mesin lokal.

cd labs/17-architecture-decision-record
go test -v ./...    # validasi parser & linter
go test -race ./... # verifikasi race-free
go run ./cmd/demo   # jalankan simulasi 3 ADR

ADR Diubah Jadi Data yang Bisa Dicek

Nilai utama lab ini adalah menjadikan keputusan arsitektur sebagai data yang bisa diuji. Linter menjaga integritas silsilah dokumen, sementara manusia fokus pada kualitas keputusan.
