Konteks Keputusan Hilang Memicu Debat Teknis Berulang

Ketika alasan pemilihan desain masa lalu lenyap, tim terjebak dalam siklus refactoring kontraproduktif. Diskusi intensif bukan berarti tim produktif jika mereka hanya mengulang perdebatan yang sama tanpa acuan rekam jejak formal.

Wiki dan Markdown Manual Cepat Mengalami Drift

Penyimpanan keputusan di wiki eksternal menyebabkan keterpisahan parah antara implementasi kode dan dokumentasi. Menaruh file markdown di repositori tidak otomatis menjaga kebenaran data jika tautan nomor dan siklus hidupnya tidak diuji mesin.

Empat Pilar Siklus Hidup Architecture Decision Record

ADR mengabadikan keputusan penting ke dalam repositori dengan sifat kekal setelah disetujui. Hanya pada jalur ini, yakni lewat validasi pipeline otomatis, silsilah keputusan terhindar dari pembaruan sepihak dan inkonsistensi nomor.

Pipeline Validasi: Dari Raw Markdown Menjadi Error List

Alur validasi memindai string dokumen, memverifikasi kelengkapan seksi teks, mengurutkan ID penomoran, lalu memverifikasi tautan graf. Pipeline ini membuktikan validasi in-memory, tetapi belum membuktikan integrasi langsung dengan git pre-commit hook.

Ekstraksi Metadata dan Seksi Wajib Lewat Regex

Parser mengekstrak nomor ID dan memeriksa keberadaan konten pada seksi Context, Decision, dan Consequences. Menggunakan regex kaku bukan berarti parser fleksibel terhadap semua dialek Markdown; parser ini sengaja membatasi diri pada konvensi baku Nygard.

var (
    titleRegex   = regexp.MustCompile(\`^#\\s+(\\d+)\\.\\s+(.+)$\`)
    statusRegex  = regexp.MustCompile(\`(?i)^Status:\\s*([A-Za-z]+)(?:\\s+by\\s+(\\d+))?\`)
    contextRegex = regexp.MustCompile(\`(?i)^##\\s+Context\`)
    decisionRegex = regexp.MustCompile(\`(?i)^##\\s+Decision\`)
)

Kerusakan dokumentasi paling berbahaya terjadi saat penggantian dilakukan sepihak atau menunjuk ke dokumen hantu. Hanya pada jalur ini linter mendeteksi ketidaksesuaian relasi dan menggagalkan merge sebelum informasi keliru menyebar ke tim.

Trade-off Penerapan ADR dan Validasi Terotomasi

Penerapan ADR menambah beban penyusunan PR karena tim harus menyepakati kata-kata keputusan dan konsekuensi. Memiliki linter tidak otomatis menjamin keputusan arsitektur benar; linter hanya menjaga integritas struktural teks, bukan kualitas logika bisnis.

Validasi Graf Konkuren Menggunakan Goroutines & Mutex

Validasi simpul graf dieksekusi secara konkuren menggunakan goroutine per record dan agregasi mutex. Simulasi ini tidak sama dengan operasi disk I/O riil pada ribuan berkas, namun membuktikan kebersihan dari race condition di memori.

var wg sync.WaitGroup
for _, r := range records {
    wg.Add(1)
    go func(rec *Record) {
        defer wg.Done()
        // Evaluasi referensi timbal balik
    }(r)
}
wg.Wait()

Transformasi: Dari Catatan Liar ke Graf Tervalidasi

Sebelum ada ADR, alasan pemilihan teknologi tercecer di arsip chat dan dokumen wiki yang tidak terawat. Menerapkan ADR dan linter bukan berarti menciptakan birokrasi kaku, melainkan mengunci kejelasan keputusan penting dengan usaha minimal.

Enforcing State Machine Siklus Hidup ADR

Tipe data Status mengikat status ADR hanya pada lima kondisi siklus hidup formal. Keputusan membatasi status ini cakupannya mengikuti test spesifik lab, mencegah masuknya istilah rancu seperti In-Review atau Draft ke cabang utama.

type Status string
const (
    StatusProposed   Status = "Proposed"
    StatusAccepted   Status = "Accepted"
    StatusSuperseded Status = "Superseded"
    StatusDeprecated Status = "Deprecated"
    StatusRejected   Status = "Rejected"
)

Invarian Penomoran Monotonik Mencegah Berkas Hilang

Linter mengumpulkan seluruh ID dan mencocokkan nilainya tepat dengan indeks i+1 setelah diurutkan. Urutan penomoran yang rapi tidak otomatis menjamin tidak ada commit yang salah rebase, tetapi mencegah celah nomor yang membingungkan auditor.

ids := make([]int, 0, len(records))
for id := range recordMap { ids = append(ids, id) }
sort.Ints(ids)
for i := 0; i < len(ids); i++ {
    if ids[i] != i+1 {
        errs = append(errs, fmt.Errorf("non-monotonic numbering"))
        break
    }
}

Deteksi Siklus Silsilah dengan Algoritma DFS 3-State

Deteksi siklus memanfaatkan algoritma pewarnaan simpul DFS tiga status: unvisited, visiting, dan visited. Hanya pada jalur ini deteksi rekursif mampu menangkap skenario loop kompleks di mana ADR 1 digantikan 2, 2 digantikan 3, dan 3 kembali menunjuk 1.

state := make(map[int]int) // 0: unvisited, 1: visiting, 2: visited
detectCycle = func(id int) {
    state[id] = 1
    if rec, ok := recordMap[id]; ok && rec.SupersededBy != 0 {
        nextID := rec.SupersededBy
        if state[nextID] == 1 {
            errs = append(errs, fmt.Errorf("cyclical supersession"))
        } else if state[nextID] == 0 { detectCycle(nextID) }
    }
    state[id] = 2
}

Verifikasi Timbal-Balik: Konsistensi Hubungan Penggantian

Linter memeriksa keselarasan dua arah antara SupersededBy dan Supersedes. Menjaga kedua deklarasi tetap sinkron bukan berarti menambah redudansi sia-sia, melainkan memastikan pembaca dokumen lama maupun baru mendapatkan visibilitas status yang utuh.

if rec.Status == StatusSuperseded {
    replacement, exists := recordMap[rec.SupersededBy]
    if !exists { localErrs = append(localErrs, fmt.Errorf("non-existent")) }
    else if replacement.Supersedes != rec.ID {
        localErrs = append(localErrs, fmt.Errorf("mismatched supersession"))
    }
}

Penolakan Berkas Cacat: Parser Guard Seksi Wajib

Pengujian unit memverifikasi bahwa parser menolak dokumen dengan judul cacat, status informal, atau seksi wajib tanpa konten. Aturan validasi ketat ini cakupannya mengikuti test suite yang menjamin setiap ADR memiliki bobot substansi arsitektur nyata.

func TestParse_Invalid(t *testing.T) {

    // ...
}

Checklist Tata Kelola Architecture Decision Record

Checklist ini merangkum disiplin perancangan ADR: penyimpanan bersama kode, penomoran urut tanpa bolong, status formal terikat, sifat kekal tanpa revisi diam-diam, tautan timbal-balik, serta validasi otomatis pada continuous integration.

Anti-Pattern Umum dalam Dokumentasi Arsitektur

Mengedit ADR lama yang sudah disetujui menghapus jejak sejarah dan memicu kebingungan mengapa keputusan itu dibuat awalnya. Menolak menulis ADR bukan berarti tim lebih gesit; hal itu hanya menunda biaya debat berkepanjangan ketika arsitek berganti.

Reproduksi Mandiri di Mesin Lokal Menggunakan Go

Seluruh mekanisme validasi ditulis menggunakan Go standard library tanpa modul eksternal. Eksperimen lokal ini memvalidasi integritas data di memori, namun production masih perlu menambahkan skrip CLI berkas dan integrasi hook commit.

cd labs/17-architecture-decision-record
go test -v ./...    # validasi parser regex dan aturan linter struktural
go test -race ./... # verifikasi validasi graf konkuren bebas data race
go run ./cmd/demo   # eksekusi demo parsing 3 ADR evolusi SaaS ERP

Prinsip Inti: Keputusan Adalah Kode yang Harus Diuji

Dokumentasi keputusan arsitektur harus diperlakukan sama dengan kode sumber aplikasi. Menyimpan dokumen tanpa mekanisme pengujian otomatis tidak otomatis membuatnya berguna; keandalan dokumentasi hadir ketika strukturnya divalidasi oleh compiler dan CI.
