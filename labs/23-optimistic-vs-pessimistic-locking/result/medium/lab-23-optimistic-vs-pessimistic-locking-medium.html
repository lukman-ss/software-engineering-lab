Optimistic vs Pessimistic Locking di Go

Motivasi

Dalam sistem konkuren, pengaturan akses ke shared state menentukan konsistensi data. Lab ini menguji pendekatan pessimistic locking via sync.Mutex dan optimistic locking via pengecekan versioning.

Batas Lab

Implementasi menggunakan pustaka standar Go. Fokus pada single process memory tanpa rely pada distributed lock engine.

Bukti Kode

// Pessimistic
mu.Lock()
defer mu.Unlock()

// Optimistic
if record.Version != expectedVersion {
    return ErrConflict
}
record.Version++

Temuan

Pessimistic locking lebih stabil untuk beban tulis tinggi dengan konflik sering. Optimistic locking unggul di skenario baca dominan dengan konflik minimal.
