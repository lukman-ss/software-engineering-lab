Memisahkan Konfigurasi dari Penggunaan: Constructor Injection vs Service Locator

Lukman / lukman-ss · Software Engineering Lab 16

Coupling Keras Merusak Testability & Evolusi

Ketika komponen bisnis menginstansiasi dependensinya sendiri, kode menjadi terkunci pada infrastruktur konkret. Pengujian terisolasi menjadi mustahil dan pergantian vendor memicu refactor besar.

Mengapa Global State & Manual Swap Gagal

Mencoba menyelesaikan coupling dengan Service Locator atau Singleton global hanya memindahkan masalah: dependensi menjadi tersembunyi dan runtime error menggantikan compile-time error.

Pemisahan Konfigurasi dari Penggunaan

Inti DI adalah memisahkan dua siklus hidup: pembuatan grafik objek di satu composition root, dan eksekusi logika domain yang hanya berinteraksi melalui kontrak interface.

Alur Dependensi: Composition Root ke Gateway

Alur kerja DI menghubungkan composition root ke gateway melalui kontrak interface. Processor hanya tahu interface PaymentGateway, sehingga implementasi konkret dapat diganti sesuka hati.

Constructor Injection: Valid at Birth

Constructor Injection memastikan objek selalu berada dalam state valid sejak dibuat. Tidak ada hidden dependency, tidak ada container import, dan compile-time type safe.

type Processor struct {
    gateway PaymentGateway // unexported field
}

func NewProcessor(g PaymentGateway) *Processor {
    return &Processor{gateway: g}
}

func (p *Processor) ProcessPayment(amount int) error {
    if amount <= 0 { return errors.New("invalid amount") }
    return p.gateway.Charge(Money{Amount: amount, Currency: "USD"})
}

Failure Path: Validasi Dini Mencegah I/O Sia-sia

DI tidak menghilangkan validasi. Guard clause domain memastikan panggilan jaringan tidak pernah dieksekusi jika input tidak valid, sementara error infrastruktur dipropagasikan secara transparan.

Client Input: ProcessPayment(-10)
  -> Guard Clause: if amount <= 0 (VALIDATION FAILURE)
  -> Return: errors.New("invalid amount")
  -> Short-Circuit: Gateway.Charge() TIDAK PERNAH DIPANGGIL

Gateway Down: MockGateway.ShouldFail = true
  -> Input Valid: ProcessPayment(50) -> Gateway.Charge(50 USD)
  -> Infrastructure Error: "gateway unavailable" dipropagasi utuh

Decision Sequence: Kapan Menggunakan Pola Tertentu

Jangan perlakukan semua objek sama. Service dengan I/O eksternal membutuhkan Constructor Injection, sedangkan value object murni harus diinstansiasi langsung tanpa perantara.

Analisis Batasan Bukti: Fakta vs Ekstrapolasi

Lab membuktikan isolasi test dan pemisahan perakitan, tetapi tidak membuktikan siklus hidup scoped/transient container maupun metrik penurunan bug di production.

Trade-off Arsitektur: Eksplisit vs Fleksibilitas

Constructor Injection tidak gratis: ia menambah boilerplate di entry point. Namun biaya ini sebanding dengan jaminan type-safety dan kemudahan pembacaan dependensi.

Pipeline Validasi & Keamanan Konkurensi

Dengan menginjeksi interface stateless dan memakai value object immutable, Processor bebas dari race condition saat diakses oleh banyak goroutine secara bersamaan.

Goroutine Client Request -> NewProcessor(mock)
  -> ProcessPayment(amount) [Stateless Validation]
  -> if amount <= 0 -> Instant Error (No I/O)
  -> Value Object: Money{Amount, USD} [Immutable, Stack-allocated]
  -> Gateway.Charge(Money) [Thread-Safe Interface Call]
Race Detector Verification: go test -race ./... -> 0 warnings

Sebelum vs Sesudah Constructor Injection

Sebelumnya, dependensi tersembunyi dan runtime error mengintai. Sesudahnya, interface membuat kontrak jelas dan compiler menjamin kelengkapan parameter sejak awal.

Bedah Anatomi: Service Locator Anti-Pattern

Service Locator tampak fleksibel, tetapi ia mengikat kelas bisnis ke API kontainer dan menyembunyikan dependensi sebenarnya dari siapapun yang membaca signature kelas.

type BadProcessor struct {
    container Container // Anti-Pattern: Mengikat ke container API
}

func (p *BadProcessor) ProcessPayment(amount int) error {
    // Opaque lookup: pembaca kode tidak tahu dependensi asli
    return p.container.GetPaymentGateway().Charge(m)
}

Value Objects Tidak Boleh Menggunakan DI

DI dicadangkan untuk service yang berinteraksi dengan infrastruktur eksternal. Struktur data murni seperti Money cukup dibuat langsung tanpa melibatkan container.

Strategi Mocking: Pengujian Cepat & Terisolasi

Dengan menginjeksi mock sederhana di unit test, kita dapat memverifikasi payload transaksi dan simulasi error tanpa menyentuh jaringan sama sekali.

type MockGateway struct {
    ChargedMoney di.Money
    ShouldFail   bool
}

func (m *MockGateway) Charge(money di.Money) error {
    if m.ShouldFail { return errors.New("gateway unavailable") }
    m.ChargedMoney = money
    return nil
}

Batas Integritas: Apa yang Tidak Diuji

Suite test memverifikasi isolasi logika unit dan propagasi error. Pengujian ini tidak membuktikan ketahanan jaringan produksi atau manajemen memori container skala besar.

Risiko Produksi: Constructor Bloat & Over-Injection

Jika konstruktor Anda membutuhkan belasan parameter, jangan cari framework auto-wiring untuk menyembunyikannya. Pecah kelas tersebut karena ia melanggar Single Responsibility Principle.

Checklist Adopsi Dependency Injection

Checklist ini menjadi panduan praktis untuk memastikan arsitektur DI tetap bersih, mudah diuji, dan bebas dari jebakan container lock-in.

Anti-Pattern: Jebakan Umum dalam Praktik DI

Hindari mengotori logika domain dengan API framework. Gunakan interface Go yang idiomatis di sisi konsumen dan jangan membuat abstraksi prematur untuk objek yang tidak perlu di-mock.

Reproduksi Mandiri & Command Runner

Eksperimen ini zero-external-dependency dan dapat direproduksi dalam waktu kurang dari satu detik pada mesin lokal manapun.

cd labs/16-dependency-injection
go test -v ./...       # Menjalankan 6 test cases (mock isolation)
go test -race ./...    # Verifikasi data race pada goroutine
go run ./cmd/demo      # Menjalankan demo perbandingan kedua pola

Prinsip Inti: Program to Interfaces, Not Implementations

Prinsip sejati DI bukan tentang framework atau anotasi canggih, melainkan tentang memisahkan concern: biarkan composition root merakit, dan biarkan modul domain mengeksekusi.
