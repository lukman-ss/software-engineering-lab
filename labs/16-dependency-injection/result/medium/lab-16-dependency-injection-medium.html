Instansiasi Langsung Mengunci Logika Domain

Ketika Processor membuat RealGateway di dalamnya, dependensi konkret terkunci. Ini bukan berarti sistem gagal seketika, tetapi setiap test terpaksa menjadi integration test yang lambat dan rapuh.

Global Singleton dan Flag Mengaburkan Kontrak

Mengandalkan singleton global tidak otomatis menyelesaikan coupling. Pendekatan ini menyembunyikan dependensi dari fungsi caller dan memicu kontaminasi state antar pengujian paralel.

Pisahkan Perakitan Objek dari Eksekusi Bisnis

Fowler menegaskan pemisahan konfigurasi dari penggunaan adalah prinsip terpenting. Objek dirakit di composition root; domain hanya pada jalur ini memproses logika bisnis murni.

IoC adalah Arah Kendali, DI adalah Bentuk Spesifik

IoC adalah konsep payung pembalikan kontrol alur. Memakai DI bukan berarti mengadopsi seluruh kontrol framework, melainkan hanya menyerahkan tanggung jawab pembuatan dependensi ke assembler eksternal.

Abstraksi Gateway dan Value Object Tanpa DI

PaymentGateway mendefinisikan kontrak Charge tunggal. Money adalah value object murni tanpa dependensi sehingga dibuat langsung. Adanya interface ini belum membuktikan gateway bebas kegagalan jaringan.

type Money struct { Amount int; Currency string }

type PaymentGateway interface {
    Charge(m Money) error
}

type RealGateway struct{}
func (g *RealGateway) Charge(m Money) error {
    fmt.Printf("RealGateway charging %d %s\n", m.Amount, m.Currency)
    return nil
}

Constructor Injection Membuat Dependensi Terlihat

NewProcessor menerima PaymentGateway secara eksplisit. Dependensi terlihat di signature fungsi. Namun, parameter interface tidak otomatis menolak nil pointer tanpa validasi guard tambahan.

type Processor struct { gateway PaymentGateway }

func NewProcessor(g PaymentGateway) *Processor {
    return &Processor{gateway: g}
}

func (p *Processor) ProcessPayment(amount int) error {
    if amount <= 0 { return errors.New("invalid amount") }
    m := Money{Amount: amount, Currency: "USD"}
    return p.gateway.Charge(m)
}

Validasi Domain Berjalan Sebelum Panggilan Gateway

DI tidak menghilangkan kewajiban validasi. Validasi amount <= 0 memastikan gateway tidak pernah dipanggil sia-sia. Hanya pada jalur ini domain bertanggung jawab atas integritas data angka.

Service Locator Menyembunyikan Dependensi Nyata

BadProcessor menerima Container alih-alih PaymentGateway. Kode tetap berjalan, tetapi bukan berarti arsitekturnya bersih: dependensi PaymentGateway tersembunyi di balik container lookup.

type Container interface { GetPaymentGateway() PaymentGateway }

type BadProcessor struct { container Container }

func NewBadProcessor(c Container) *BadProcessor {
    return &BadProcessor{container: c}
}

func (p *BadProcessor) ProcessPayment(amount int) error {
    if amount <= 0 { return errors.New("invalid amount") }
    m := Money{Amount: amount, Currency: "USD"}
    return p.container.GetPaymentGateway().Charge(m)
}

Composition Root Menjadi Titik Tunggal Perakitan

main.go bertindak sebagai composition root. RealGateway dibuat satu kali lalu disuntikkan. Simulasi ini tidak sama dengan container enterprise kompleks; ini manual wiring murni Go.

func main() {
    realGateway := &di.RealGateway{}

    // Constructor Injection (Bersih & Eksplisit)
    processor := di.NewProcessor(realGateway)
    _ = processor.ProcessPayment(100)

    // Service Locator (Anti-Pattern Demo)
    container := &SimpleContainer{gateway: realGateway}
    badProcessor := di.NewBadProcessor(container)
    _ = badProcessor.ProcessPayment(200)
}

Test Double Menggantikan Infrastruktur Jaringan

MockGateway menggantikan RealGateway sepenuhnya saat pengujian. Variabel ShouldFail memicu simulasi error jaringan secara deterministik, namun cakupannya mengikuti test skenario sederhana ini.

type MockGateway struct {
    ChargedMoney di.Money
    ShouldFail   bool
}

func (m *MockGateway) Charge(money di.Money) error {
    if m.ShouldFail {
        return errors.New("gateway unavailable")
    }
    m.ChargedMoney = money
    return nil
}

Batas Bukti Lab: Yang Dibuktikan vs Belum

Lab ini membuktikan decouling interface dan isolasi mock. Hasil ini belum membuktikan perbandingan performa DI container otomatis berskala besar maupun pengelolaan lifecycle kompleks.

Value Object Diinstansiasi Langsung Tanpa DI

Mengabstraksi semua objek ke dalam DI adalah anti-pattern over-engineering. Value object seperti Money dibuat langsung; ini bukan berarti mengorbankan prinsip decoupling arsitektur.

Parameter Terlalu Banyak Menandakan SRP Violation

Banyak parameter konstruktor adalah alarm bahwa kelas melanggar SRP. Mengganti konstruktor gemuk dengan container tidak otomatis menyehatkan desain; solusinya adalah refactoring service.

Rekomendasi Industri: Hindari Menginjeksi Container

PSR-11 melarang pengoperan container ke objek dengan klausul SHOULD NOT. Ini bukan berarti container ilegal, tetapi peringatan keras bahwa domain tidak boleh bergantung pada mekanisme lookup.

Race Clean di Test Bukan Bukti Lifecycle Production Aman

Status race-clean di test memvalidasi alur fungsi yang diuji. Namun, production masih perlu validasi konkurensi terpisah jika implementasi gateway berbagi koneksi socket atau mutable cache.

Biaya Tersembunyi: Kapan DI Tidak Diperlukan?

DI bukan obat mujarab gratis. Memisahkan konstruksi dari penggunaan menyulitkan tracing alur kode. Menambahkan abstraksi tidak otomatis menguntungkan jika modul tersebut tidak pernah diganti.

Checklist Penerapan Dependency Injection di Go

Checklist ini merangkum aturan main DI: interface pada consumer, constructor injection eksplisit, composition root tunggal, dan instansiasi langsung untuk tipe data murni.

Anti-Pattern Umum dalam Penerapan DI

Menggunakan container sebagai god object merusak encapsulation. Menerapkan interface untuk semua struct bukan berarti sistem menjadi bersih, melainkan menciptakan interface pollution yang melelahkan.

Kesimpulan Inti: Konstruksi Terpisah dari Penggunaan

DI memisahkan perakitan objek dari logika domain. Interface memungkinkan isolasi pengujian secara deterministik. Namun, DI tidak otomatis menjamin keamanan runtime tanpa validasi menyeluruh.
