Infrastruktur Terkunci di Logika Bisnis

Kopling keras antara logika domain dan implementasi infrastruktur merusak evolvability sistem. Pengujian unit menjadi mustahil dilakukan secara murni tanpa network overhead.

Review Manual Melewatkan Hidden Dependencies

Reviewer manusia melihat parameter Container dan menganggap modularitas tercapai. Faktanya, Service Locator hanya memindahkan kopling dari compile-time ke runtime.

Separation of Configuration from Use

Prinsip paling fundamental dari DI bukanlah framework atau container, melainkan pemisahan waktu pembuatan objek dari waktu penggunaan objek.

Pipeline Alur Eksekusi Dependency Injection

Pipeline memperlihatkan batasan tanggung jawab yang jelas: composition root menangani konstruksi, processor menangani validasi, dan gateway menangani charge.

Constructor Injection: Valid State at Birth

Dengan Constructor Injection, Processor tidak mungkin dibuat dalam keadaan setengah matang. Signature constructor menyatakan secara gamblang apa yang dibutuhkan.

type Processor struct {
    gateway PaymentGateway
}

func NewProcessor(g PaymentGateway) *Processor {
    return &Processor{gateway: g}
}

Failure Path: Pencegahan Eksekusi I/O Sia-sia

DI tidak menghilangkan kebutuhan validasi. Pre-check di Processor memastikan gateway tidak pernah dipanggil ketika parameter bisnis tidak valid.

Batasan Bukti: Cakupan Verifikasi Lab

Lab membuktikan keunggulan struktural dan kemudahan pengujian unit. Lab tidak mengukur klaim performa runtime microbenchmark atau lifecycle container tingkat lanjut.

Trade-off: Kontrol Bersih vs Biaya Boilerplate

DI bukan solusi tanpa biaya. Keuntungan testability dan fleksibilitas harus diimbangi dengan kehati-hatian agar constructor tidak membengkak karena service terlalu besar.

Pipeline Validasi & Thread-Safety

Karena Processor tidak menyimpan state yang dapat dimutasi (hanya menyimpan reference interface gateway yang stateless), pemrosesan pembayaran bebas dari race condition.

Sebelum vs Sesudah Penerapan DI

Sebelumnya, setiap pengujian bergantung pada kestabilan koneksi internet ke vendor. Sesudah DI, seluruh skenario ekstrim dapat disimulasikan seketika di memori lokal.

Test Suite 01: Verifikasi Happy Path Terisolasi

Test happy path membuktikan bahwa Processor mendelegasikan data secara akurat ke gateway tanpa perlu mengetahui implementasi di belakang interface.

Test Suite 02: Propagasi Kegagalan Gateway

Menguji kegagalan gateway pada arsitektur tightly coupled sangat sulit. Dengan DI, kegagalan vendor dapat disimulasikan hanya dengan mengaktifkan flag pada test double.

Test Suite 03: Short-Circuit Invalid Amount

Kombinasi assertion error dan pemeriksaan nilai 0 pada mock membuktikan bahwa validasi pre-check berhasil menghentikan alur sebelum mencapai lapisan infrastruktur.

Desain Rasional: Value Object Bebas DI

Kesalahan umum pemula adalah menginjeksikan segalanya. Value object seperti Money, Date, atau Alamat adalah representasi data murni yang harus diinstansiasi langsung.

Bahaya Service Locator: PSR-11 Warning

Service Locator adalah ilusi decoupling. Alih-alih terikat pada RealGateway, kelas justru terikat erat pada API Container yang lebih rumit untuk di-mock.

Checklist Adopsi Dependency Injection

Checklist ini menjadi panduan praktis dalam code review untuk mencegah bocornya dependensi konkret ke dalam domain logic tim.

Tiga Anti-Pattern Umum Seputar DI

DI bukan alasan untuk membiarkan sebuah kelas menangani terlalu banyak hal. Jika parameter konstruktor membengkak, solusinya adalah memecah kelas, bukan memakai Service Locator.

Reproduksi Mandiri Suite Pengujian

Lab ini sepenuhnya berbasis Go standard library tanpa external dependencies. Seluruh verifikasi dapat direproduksi dalam hitungan detik di lingkungan apa pun.

cd labs/16-dependency-injection
go test -v ./...       # Verifikasi 6 skenario test suite
go test -race ./...    # Verifikasi thread-safety zero data race
go run ./cmd/demo      # Eksekusi demo komparasi Ctor vs Locator

Prinsip Arsitektur: Hollywood Principle

Dependency Injection adalah perwujudan konkret dari Dependency Inversion Principle. Dengan membalik kontrol pembuatan objek, sistem menjadi adaptif terhadap perubahan zaman.
